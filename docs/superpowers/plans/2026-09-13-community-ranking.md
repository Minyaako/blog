## 三个交付阶段

1. **投稿闭环**：SQLite 与独立用户身份映射，提交/撤回/审批/退回/上下架事务，同源 API、会话与权限检查。验证重复提交、状态竞态、越权、旧版本保护和服务重启持久性。
2. **网页体验**：复用站点样式的公开列表/详情、同页编辑、新建、我的投稿及管理页。接入本地草稿、拖拽/键盘、确切来源、历史和简单差异；验证桌面/触屏/减少动态效果及错误恢复。
3. **运行与交付**：Node 适配器、持久目录、隔离候选数据库、显式迁移、备份/恢复、静态资源与搜索兼容，执行集成和独立审查。生产凭据、外部认证接入和服务器部署仅在条件齐备且获得相应授权后执行。

## 固定实现边界

- 业务使用内部 userId；登录来源以 provider + subject 映射，不把 GitHub 写进业务表或权限。
- 一个 SQLite 数据库、完整 JSON 快照、一个当前版本指针；版本只在审批事务中产生。
- 已发送请求键与正文固定；同键重试不会重复建榜。每榜一条待审稿，过期基线拒绝。
- 页面复用原有主题和字体。编辑器保持有序列表，不加 UI 框架、动画库或通用工作流抽象。
- 数据库不进入 Git/镜像；没有生产数据库时不能静默创建空库掩盖错误。

## 认证接入决策

用户已确认复用现有 Waline（此前误称 Sveltia）。仅复用已部署的登录能力，不新建账号密码系统、不新增 QQ/Facebook 配置、不自动继承评论管理员权限。

接入约定：固定配置的 Waline `/api/token` 由榜单服务端携带 Bearer 和站点 Origin 查询；只有成功返回稳定 objectId 的已验证用户可映射到内部账号（按 Waline 实例 + objectId，而非邮箱/昵称）。登录成功换发既有 HttpOnly/同站 Cookie，会话随附 HttpOnly 上游凭据，仅用于逐请求验证；数据库不存 Waline token，无 schema 迁移。私有读取/写入均验证上游身份和本地会话一致；超时/故障拒绝操作、不误判为另一账号。公开页面不依赖 Waline。

浏览器复用现有 Waline storage 登录状态，使用校验 origin/source 的登录窗口；切换账号暂停旧草稿而不迁移归属，投稿前重新同步。退出清除本站会话及本浏览器 Waline 登录状态。Waline 当前 token DELETE 不撤销全设备 JWT，不能声称实现全设备注销；上游封禁/失效由逐次查询处理。本地回归使用独立假 Waline HTTP 服务，不在业务服务增加测试登录后门。

验收：无效/过期/封禁 token、上游异常、伪造身份/角色、跨站登录、Cookie/CSRF、同 ID 跨实例、已登录评论复用、弹窗来源、账号切换草稿保护与退出同步。保留既有投稿回归；独立审查后更新证据。恢复方式为停写并回滚代码/配置，清空本站 sessions 使旧会话失效，不恢复旧投稿数据库。
