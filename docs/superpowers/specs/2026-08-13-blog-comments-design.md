# 博客评论区首版设计

状态：已确认
日期：2026-08-13

## 目标

为 `gsk.minyako.top` 的文章页增加一个简单、可复用、可独立运维的评论区。首版使用自托管 Waline 和 SQLite，允许游客立即发表评论，并提供单管理员后台进行查看、标记和删除。

实现应保持薄而清晰：Astro 只拥有一个评论适配器和一个评论区组件；Waline 负责评论业务；评论服务拥有自己的部署、数据和备份生命周期。后续替换提供方时，文章布局和文章内容不应需要修改。

## 首版范围

首版包含：

- 游客使用必填昵称和选填邮箱发表评论；
- 邮箱不公开，首版不发送邮件；
- 基础 Markdown：链接、引用、行内代码和代码块；
- 回复功能；所有回复最多显示一层缩进，更深回复仍保留回复目标；
- 评论立即公开；
- 基于 IP 的基础发布间隔限制；
- 单管理员通过 Waline 管理后台查看、标记和删除评论；
- 评论服务独立部署、SQLite 持久化、备份和恢复演练；
- 明暗主题、移动端、键盘操作、懒加载和失败降级。

首版不包含：

- GitHub OAuth、邮箱登录或访客账号；
- 邮件通知；
- 浏览量、点赞、文章表情反应和评论表情包；
- 图片上传；
- 评论预审、验证码、蜜罐、自定义敏感词或第三方反垃圾服务；
- 自定义评论后端或自建管理后台；
- 多管理员和复杂权限；
- 访客头像和第三方头像请求。

## 架构与责任边界

博客继续使用 Astro 静态输出，不引入 SSR 或博客数据库。评论服务运行在 `comments.minyako.top`，由共享 Caddy 代理到 `server_proxy` Docker 网络中的 Waline 容器。Waline 不映射公网主机端口。

```text
文章永久 ID
  -> Astro 评论区组件
  -> 薄 CommentProvider 适配器
  -> https://comments.minyako.top
  -> Waline
  -> SQLite 持久数据
```

文章的永久 `id` 是唯一评论键。适配器把它传给 Waline 的 `path`，不得使用文章 URL。文章改名、移动分类、修改 slug 或迁移域名时，已有评论仍与同一文章关联。

现有 `CommentProvider` 契约收窄为本次真正需要的挂载和销毁能力，不保留未使用的浏览量方法。只有适配器可以导入和配置 `@waline/client`；文章布局只渲染带永久文章 ID 的评论区组件。

评论服务采用独立 Compose 项目。静态博客发布和回滚不得启动、停止、替换或删除评论容器及评论数据；Waline 发布也不触发博客构建。博客仓库可以维护评论服务所需的应用级配置和运行手册，共享域名路由仍由 `server-infra` 仓库维护。

## 前端行为

评论区位于相关文章和前后篇导航之后，并继续设置 `data-pagefind-ignore`。初始 HTML 提供标题和轻量加载占位，不包含 Waline 客户端代码。

当评论区接近视口时，`IntersectionObserver` 触发一次动态导入并挂载 Waline。项目把固定版本的 `@waline/client` 安装为依赖，由博客构建产出客户端资源，不在运行时依赖公共 CDN。旧浏览器或观察器不可用时，适配器直接加载，保证功能可达。

Waline 客户端采用以下固定策略：

- `serverURL: https://comments.minyako.top`；
- `path` 使用文章永久 `id`；
- `lang: zh-CN`；
- `meta: ['nick', 'mail']`；
- `requiredMeta: ['nick']`；
- `login: 'disable'`；
- `imageUploader: false`；
- `emoji: false`；
- `reaction: false`；
- 不初始化浏览量功能；
- 根评论按最新优先排列。

界面文案明确说明：昵称必填，邮箱选填且不会公开，首版不发送邮件。网站字段不显示。评论继续由 Waline 的安全 Markdown 渲染处理，原始 HTML 不作为受支持输入，图片上传入口被关闭。

访客头像在首版隐藏，同时关闭第三方头像代理或头像 URL 请求，避免把邮箱摘要发送给外部头像服务。管理员标识可由 Waline 后台保留，但不因此开放访客登录。

回复数据保持 Waline 原有父子关系和回复目标。样式只允许根评论与回复层两级视觉层次：所有非根评论使用同一缩进，后续层级不得继续向右累加。移动端使用更小但仍清晰的单层缩进。

评论组件跟随站点现有设计令牌覆盖 Waline CSS 变量，支持明暗主题、清晰焦点和长内容换行。只做必要的样式适配，不复制或重写 Waline 的表单、列表或后台。

## 加载与失败处理

评论客户端加载失败或 API 不可用时，组件显示紧凑的“评论暂时不可用”状态和重试按钮。重试重新创建适配器实例；同一实例不得重复挂载。失败不能影响正文、导航、搜索或其他静态页面。

评论提交被限流或服务端拒绝时，保留 Waline 的可理解错误反馈，不清空访客正在编辑的内容。页面离开或 Astro 页面生命周期切换时调用 `dispose()`，释放观察器和 Waline 客户端实例，避免重复事件监听。

## 服务端配置

Waline 使用经验证的稳定版本镜像；实现时同时固定版本标签和镜像摘要，并在运行手册记录升级方式，禁止使用 `latest`。容器仅加入外部网络 `server_proxy`，使用健康检查和 `restart: unless-stopped`，不开放主机端口。

首版关键配置为：

- `SITE_URL=https://gsk.minyako.top`；
- `SERVER_URL=https://comments.minyako.top`；
- `SECURE_DOMAINS` 只允许 `gsk.minyako.top` 和 `comments.minyako.top`；
- `COMMENT_AUDIT=false`；
- `IPQPS=60`，同一 IP 两次发布至少间隔 60 秒；
- `AKISMET_KEY=false`，关闭 Waline 默认 Akismet；
- `DISABLE_USERAGENT=true`；
- `DISABLE_REGION=true`；
- 关闭头像代理并使用不产生外部请求的头像配置；
- 不设置 SMTP、验证码、OAuth 或浏览量相关配置。

SQLite 数据目录使用专用持久挂载。`JWT_TOKEN` 等秘密保存在 `/srv/secrets/blog-comments/` 下的受限环境文件中，不进入 Git、镜像或命令输出。非秘密部署配置、示例环境变量名和运维步骤可以提交。

## 管理员初始化

Waline 的首个注册用户会成为管理员，因此初始化必须先于公网开放：

1. 启动评论容器，但暂不启用正式 Caddy 路由；
2. 执行者通过服务器本机访问或 SSH 隧道进入注册页面，使用用户在会话中提供的管理员邮箱和临时密码创建唯一管理员；
3. 验证管理员登录、评论列表和删除能力；管理员邮箱和临时密码不得写入 Git、命令行参数、日志或计划文档；
4. 保持访客端 `login: 'disable'`，博客页面不提供注册或登录入口；
5. 最后启用 `comments.minyako.top` 路由并执行生产验收。

管理员使用 `https://comments.minyako.top/ui` 管理评论。首版不额外开发博客管理页面。

管理员注册验证成功后、正式公网路由仍未开放时，通过用户已配置的 QQ 通知通道发送一次简短提醒，请用户立即修改临时密码。随后暂停上线流程；只有用户确认密码已经修改，才可以开放正式公网路由。提醒不得包含管理员邮箱、密码、JWT、服务器日志或其他秘密；QQ 不作为密钥传输通道。

“单管理员”表示首版只创建和维护一个管理员身份，不承诺修改 Waline 的账户系统或自建注册封锁逻辑。若未来确实出现公开注册滥用，再单独评估由 Waline 配置或网关策略限制相关端点。

## 数据备份与恢复

评论数据不受博客镜像、博客发布状态或博客回滚保护。SQLite 数据使用独立备份任务：

- 每日生成一致性快照，保留最近 14 份；
- 每周保留一份，共保留 8 周；
- 使用 SQLite 一致性备份方式创建快照，不直接复制正在写入的数据库文件；
- 快照压缩后生成校验值；
- 备份目录位于服务器既有 `/srv/backups` 体系内，权限仅授予必要运维账号。

首次上线前完成一次恢复演练：把备份恢复到临时目录，以临时容器验证根评论、回复关系和管理员登录。临时恢复不得连接正式域名或覆盖生产数据。

Waline 升级前先创建并校验备份，记录当前镜像版本和摘要。升级失败优先恢复旧镜像；只有确认数据库发生不兼容迁移时，才从备份恢复数据库。

## 测试与验收

自动化测试聚焦稳定边界，不测试 Waline 自身内部实现：

- 单元测试验证永久文章 ID、适配器配置、一次性挂载、重试和销毁；
- 组件或浏览器测试验证懒加载、昵称必填、邮箱选填、网站字段隐藏，以及禁用登录、图片上传、表情和浏览量；
- 浏览器测试验证所有回复最多一层视觉缩进；
- 可访问性和视觉测试覆盖明暗主题、桌面和移动端、键盘焦点、长内容及失败状态；
- 搜索测试确认评论区不会进入 Pagefind；
- 配置测试验证固定镜像、持久挂载、秘密路径、网络隔离、健康检查和关键 Waline 环境变量；
- 基础设施测试验证 `comments.minyako.top` 的 Caddy 路由只指向评论服务。

生产验收使用专门测试文章依次完成：

1. 发布根评论；
2. 创建至少两级回复并确认只显示一层缩进；
3. 触发 60 秒发布间隔限制；
4. 在管理后台标记并删除测试评论；
5. 暂停评论容器，确认文章仍可阅读且重试状态正确；
6. 恢复服务并确认评论重新加载；
7. 完成一次备份恢复演练。

## 简单性与复用约束

首版以少量清晰边界为准，不为了潜在未来需求增加抽象：

- 一个评论区组件；
- 一个薄 `CommentProvider`/Waline 适配器；
- 一个独立 Waline Compose 服务；
- 一套最小备份与恢复脚本；
- 一份部署和恢复运行手册。

不建立通用插件框架、评论领域模型、额外 API 网关、自定义管理 UI 或多数据库抽象。未来只有在真实需求出现时，才在现有稳定文章 ID 和提供方边界后替换实现。

实施计划应按少量端到端阶段组织，例如“前端接入”“服务部署与数据保护”“生产验收”，每个阶段交付可验证结果。不要把单个配置项、单个样式选择器或每条断言拆成独立任务。

## 完成标准

- 文章页可使用昵称发表评论，邮箱保持选填和不公开；
- 评论和回复立即可见，回复视觉缩进最多一层；
- 评论客户端延迟加载，故障不影响正文；
- 登录、邮件、图片、浏览量、验证码和额外反垃圾能力均未启用；
- 单管理员可以在 Waline 后台查看、标记和删除评论；
- 评论服务仅通过 Caddy 暴露，秘密不进入 Git；
- SQLite 数据跨博客和评论容器发布保持不变；
- 备份保留策略和实际恢复演练均有记录；
- 自动化检查与生产验收全部通过。
